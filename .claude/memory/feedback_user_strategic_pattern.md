**Pattern observed across this session and prior:**
- User wants options laid out BEFORE implementation, especially for
  any path that's multi-day or affects strategic direction.
- "Do it" / "keep going" means proceed with the SPECIFIC step just
  proposed, not commit to an open-ended grind.
- User pushes back hard on overcommitment ("you said 1-2 weeks, it's
  actually months") and on suggestions made without thought (writelog
  replay).
- User explicitly invoked "let's discuss before deciding" as a working
  agreement during cleanup work.

**Why:** User has burned multiple sessions with me being optimistic
about wrong paths. They value honesty about scope over enthusiasm.
They make strategic decisions; I implement. Reversing this wastes
their time.

**How to apply:**
- For any work >1 day, explicitly enumerate options A/B/C with honest
  cost estimates and tradeoffs BEFORE starting. Wait for direction.
- Estimates: be conservative. If unsure between 1 week and 1 month,
  say "1-3 weeks; could be more if X." Never round down.
- After completing a discrete step, REPORT and PAUSE for next
  direction. Don't grind toward an inferred goal.
- When user says "do X" and X has a known dependency Y, ask which
  approach to Y first rather than picking one silently.
- When proposing a strategic shift (changing the project direction),
  give the user time to push back — don't roll into implementation.
