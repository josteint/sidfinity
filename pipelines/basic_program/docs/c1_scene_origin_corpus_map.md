## 1. The 100% BASIC Project (2013-2015)

### What it is
A personal project by **Alan Bond**, a C64 scene composer, to write music exclusively
in Commodore BASIC V2. He produced 62 tunes spread across three annual releases
(2013: 20 tunes; 2014: 17 tunes; 2015: 25 tunes), all in HVSC under
`MUSICIANS/B/Bond_Alan/`. The project name appears verbatim in every HVSC `released`
field: `"2013 The 100% BASIC Project"`, `"2014 The 100% BASIC Project"`, `"2015 The
100% BASIC Project"`.

### CSDb presence
The project does NOT have a group page on CSDb (searches for "100% BASIC Project"
as a group return no results). Alan Bond does appear as a scener in the CSDb SID
database (79 SID entries listed), but without a formal group page. His earlier
non-BASIC work (PSIDs: "Aztec quick-step", "Double Lizard", etc.) dates from
1988-1993. The BASIC work is a 2013+ revival.

### Programming style
Alan Bond's BASIC tunes span multiple difficulty classes:

**Algorithmic / ROM-reading** (the hardest class):
```
1 S=54272:M=57272:POKES+24,15:POKES+6,255:POKES+4,81:POKES+13,255:POKES+11,23
4 POKES+1,PEEK(M)/28:POKES+8,TIANDPEEK(M+64):M=M+.2:GOTO4
```
`M=57272` ($DF98) is in the C64's I/O area; the "melody" is generated by reading
successive bytes through ROM/RAM and dividing by 28. `TI` is the jiffy timer.
This is nondeterministic between runs (timer-dependent) and needs bit-exact
BASIC FP arithmetic to reproduce.

**Pseudo-random / RND-driven**:
```
(Argument_Emulator) POKES+1,5+(INT(RND(1)*2)*8):D=INT(RND(1)*2):...
(Glass_Jaw) T=T+1AND127:... POKES+3,TANDA:POKES+10,TANDB:...
```
Uses `RND(-seed)` to seed the RNG deterministically, then `RND(1)` for variation.
Reproducible only if the RNG seed is captured.

**Table-driven** (tractable):
```
(Two_Lines_of_Code_2) FORL=1TO15STEP7:POKES+L,PEEK(M+Z+L*9)AND28:NEXT:Z=Z+1AND7
```
Reads from a fixed ROM region (`M=40960 = $A000` = BASIC ROM) in a fixed pattern.
Deterministic.

A key tune is `No_SID_Pokes_Used_BASIC.sid` (2014) — presumably generates
"music" via the BASIC interpreter's side-effects on the SID chip WITHOUT explicit
POKE statements. This is the extreme of the algorithmic class.

### Source availability
No source listing collection or separate distribution found online. The BASIC
programs are embedded in the RSID files and recoverable by detokenization.
The HVSC SIDs ARE the source archive.

## 2. Commodore Official (1982) — 30 tunes

### Programmer's Reference Guide examples (10 tunes)
`DEMOS/Commodore/C_Prog_Ref_Guide_example_01..10_BASIC.sid`
Released: `1982 Commodore`

These are the BASIC sound example programs from Chapter 4 of the _Commodore 64
Programmer's Reference Guide_ (1982, Commodore Business Machines). The guide is
fully available at:
- https://archive.org/details/Commodore_64_Programmers_Reference_Guide_1983_Commodore
- PDF mirror: https://www.commodore.ca/manuals/c64_programmers_reference/

Content confirmed by detokenization: examples 01-10 map to the numbered
programs in the PRG Chapter 4. Examples 01, 03, 04 are the same tune (twinkle
melody) with different ADSR/waveform values — they are the textbook "change one
parameter" variant series. Example 05 uses RING MODULATION + FILTER
(`POKES+24,143`). Example 07/08/09/10 are filter/noise/envelope demos.

Example 01 plays "Twinkle Twinkle Little Star" via DATA table; the SID write
recipe is:
```
S=54272
FOR L=S TO S+24: POKE L,0: NEXT  ← clear all SID registers
POKE S+5, 9: POKE S+6, 0         ← attack/decay = 0x09, sustain/release = 0x00
POKE S+24, 15                    ← master volume = 15
READ HF, LF, DR                  ← read (freq_hi, freq_lo, duration) from DATA
POKE S+1, HF: POKE S, LF        ← set frequency
POKE S+4, 33                     ← gate ON, sawtooth wave
FOR T=1 TO DR: NEXT              ← busy-wait duration
POKE S+4, 32                     ← gate OFF (32 = keep sawtooth, gate=0)
```
The SID register-to-offset mapping (S=54272):
- S+0 = 54272 = freq lo voice 1
- S+1 = 54273 = freq hi voice 1
- S+4 = 54276 = control (gate, waveform)
- S+5 = 54277 = attack/decay
- S+6 = 54278 = sustain/release
- S+24 = 54296 = master volume + filter

### Commodore User's Guide examples (2 tunes, PAL + NTSC variants)
`Commodore_Users_Guide_PAL_BASIC.sid`, `Commodore_Users_Guide_NTSC_BASIC.sid`
From the bundled _Commodore 64 User's Guide_ (1982). PAL and NTSC variants have
different frequency values for the same pitches (the SID clock differs: PAL =
985248 Hz, NTSC = 1022727 Hz), explaining the two versions.

### Commodore demo disk examples (M1 Musik, M2 Synthesizer, M5 Gong etc.)
`M1_Musik_BASIC.sid`, `M2_Synthesizer_BASIC.sid`, `M5_Gong_BASIC.sid` etc.
These are from the C64 "demo disk" bundled with early machines. M1 is confirmed
by its own REM comment: `REM "M1 MUSIK" FROM C64 DEMO DISK`. M5 Gong is a simple
ring/filter demo. M2 Synthesizer is an INTERACTIVE BASIC synthesizer that reads
keys and maps them to SID registers in real time.

Other confirmed Commodore-sourced tunes include classical arrangements:
`Fugue_in_G_Minor_J_S_Bach_BASIC.sid` (author: Andy Toy, 1983 Commodore),
`Commodore_64_Christmas_Album_BASIC.sid` (Wayne Eastwood, 1983 Commodore), and
a set of Bach/Handel pieces (`Gigue`, `Minuet`, `Polonaise`, `Invention`).

## 4. Family Computing Magazine (1983-1988) — 24 tunes

### Sources
Joey Latimer was a **founding contributor and editor** at Family Computing (and its
sister publication K-Power, Scholastic Inc.) starting 1983. He created "MicroTones",
described as "the first computer music column I know of in a magazine" (per
joeylatimer.com). The column published type-in C64 BASIC music listings.

All 22 Latimer tunes in HVSC appear in `MUSICIANS/L/Latimer_Joey/` with `released`
indicating "Family Computing" (specific years 1983-1988). Two additional tunes are in
`DEMOS/A-F/Ahoy_Magazine_BASIC.sid` (David Barron, 1986 Ahoy! Magazine) and similar.

Joey Latimer's website (joeylatimer.com/history.html) offers PDF downloads of
selected Family Computing and K-Power articles, including the MicroTones music columns.

**Family Computing archive** (all 64 issues, Sep 1983 – Dec 1988):
https://archive.org/details/FamilyComputingIssue041983Dec

## POKE Recipe: The Standard C64 BASIC SID Pattern

All magazine listings and tutorial books teach essentially the same recipe:

```basic
S = 54272          ← SID base address ($D400)
FOR L = S TO S+24: POKE L, 0: NEXT   ← clear all SID registers

← Set up voice 1:
POKE S+5, 9        ← attack=0, decay=9  ($D405)
POKE S+6, 0        ← sustain=0, release=0 ($D406)
POKE S+24, 15      ← volume=15 ($D418)

← Play a note from DATA table (HF=freq hi, LF=freq lo, DR=duration):
READ HF, LF, DR
POKE S+1, HF       ← freq hi ($D401)
POKE S, LF         ← freq lo ($D400)
POKE S+4, 33       ← gate ON + sawtooth wave ($D404 = %00100001)
FOR T=1 TO DR: NEXT ← busy-wait
POKE S+4, 32       ← gate OFF ($D404 = %00100000)
```

**Register map (from PRG):**
| POKE addr | Offset | Register | Typical use in BASIC listings |
|-----------|--------|----------|-------------------------------|
| 54272 | S+0  | Voice 1 freq lo | note lo byte |
| 54273 | S+1  | Voice 1 freq hi | note hi byte |
| 54276 | S+4  | Voice 1 control | 33=gate+sawtooth; 81=gate+pulse; 17=gate+triangle |
| 54277 | S+5  | Voice 1 A/D     | 0x09 = A:0 D:9 |
| 54278 | S+6  | Voice 1 S/R     | 0x00 = S:0 R:0 |
| 54279-54285 | S+7..S+13 | Voice 2 | same layout |
| 54286-54292 | S+14..S+20 | Voice 3 | same layout |
| 54293 | S+21 | Filter cutoff lo | |
| 54294 | S+22 | Filter cutoff hi | |
| 54295 | S+23 | Filter control  | resonance + routing |
| 54296 | S+24 | Volume + filter mode | 15=max volume, 143=filter on |

Duration is always a busy-wait FOR loop; tempo varies across listings from
`FOR T=1 TO 50` (very fast) to `FOR T=1 TO 1000` (slow). No VBI sync.
