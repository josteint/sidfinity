### C21 — Trichotomy-verdict alignment (rebuild emits its own init)
- **The problem class:** under the init trichotomy the rebuild's init writes are
  a universal reset + typed priming, structurally different from the original's
  init sequence — so a flat prefix compare diverges at write 0. The verdict must
  (A) check the end-of-init chip STATE matches and (B) compare the PLAY streams
  after aligning past both inits.
- **Two implementations now exist (recorded as a CONSULT MISS, 2026-07-03):**
  `pipelines/hubbard/verify_cycle._trichotomy_compare` (FC universal_reset:
  recovers the alignment as a stream SHIFT d, then Check A + aligned compare +
  close-length tolerance) and `pipelines/basic_program/usf_roundtrip.
  _compare_music` + `_split_aligned` (the rebuild's init length is KNOWN from
  the typed model, and the orig's split point is found by locating the
  rebuild's first 8 music writes in the orig stream — needed because a
  gate-on-based split misfires when init PRIMES a gate/freq seed, and the
  BASIC "init" is a minutes-long setup phase rather than a fixed-length
  prefix). The basic_program variant was written WITHOUT consulting this
  ledger; whether shift-recovery could have served is unassessed. Move-1
  factor-candidate: one shared trichotomy verdict with pluggable alignment
  (shift-recovery | known-length + probe).
- **Third occurrence — ASYMMETRIC OBSERVATION of the init prefix (DMC r128b,
  2026-07-28, Kordiaukis_01_2SID chip 2 → FULL).** The trichotomy verdict is
  only sound when BOTH streams carry their init prefixes (or neither). The
  per-IRQ capture (`--writelog-per-irq`) DROPS writes before the first play
  entry — but an original that DEFERS one chip's init burst into an early
  play() has that burst CAPTURED (it's inside a play bucket) while the
  rebuild's init-time writes are dropped: Check A then compares the orig's
  primed chip state against invisible defaults — an artifact, while a flat
  full-length capture proves is_full. FIX = symmetric observation, never
  deferring the rebuild's init to match (that reproduces the orig's init
  TIMING — anti-trichotomy): siddump now emits the dropped prefix as a `|N`
  chunk; `writelog_per_irq_capture(keep_init=True)` prepends it as a leading
  frame; the DMC v4 verdict paths pass it, and shift recovery + Check A work
  on real states. ⚠ SIDE EFFECT, deliberate: Check A had been VACUOUS for
  every CIA member (both inits dropped → state 0 vs 0); keep_init makes it
  real — a strictening that needs a prior-FULL CIA sample gate when adopted
  by another family's verdict path (v4 gate: 22/22 FULL). Occurrence detail:
  [[project_dmc]] r128b.
- **Status:** factor-candidate (2× implementations; 3 occurrences).
- **Consumers:** FC standard (`compare_instruction_stream(mode='trichotomy')`),
  basic_program NF stage 2+, DMC v4 CIA verdict
  (`writelog_per_irq_capture(keep_init=True)` + trichotomy).

- **3rd implementation site + the INIT-SPILL form (2026-08-13, verify_dmc):**
  a vblank orig whose INIT runs LONGER than one frame (Rowdy's relocating
  wrapper: bank + copy ~10 pages + the copied player's init = 2-3 frames)
  puts its init WRITES into the flat capture's frames 1+ — the flat
  trichotomy compare then misaligns from write 0 (Check A samples MID-init
  state; the "play stream" opens with init writes). CURE = the Kordiaukis
  capture machinery applied as a RETRY: when the flat trichotomy verdict
  fails, recapture BOTH sides `writelog_per_irq_capture(keep_init=True)` —
  there the init prefix is everything before the first play ENTRY,
  immune to bucket spill — Check A = last-write-per-register over the |N
  init chunk (KEPT — dropping it is a C15 verdict relaxation; the first
  draft made exactly that mistake), play verdict = the ratified CIA-branch
  flat compare + length tolerance. FULL members never reach the retry
  (zero-regression by construction); validated by a full f2 re-batch with
  0 verdict flips. The retry's real value beyond verdicts: it converts a
  spill-misaligned compare into an honest per-play localization.

- **4th implementation site — PER-PLAY granularity, and a fresh CONSULT MISS
  (2026-09-01, `tools/write_timing_delta._recover_shift` +
  `_recover_chip_shift`).** A read-only measurement tool that regroups both
  write logs into true `play()` invocations hit this class in a new unit: not
  a shift in the flat WRITE stream but a shift in the PLAY INDEX. Same cause
  — the rebuild's init takes a different number of IRQs, so its play 0 is not
  the original's play 0 (Ed/Go_Funk: 460 plays vs 461). Assuming 0 reported
  356 of 390 plays as content-mismatched where the true offset (+1) gives 31,
  and — worse than the count — the plays that coincided at shift 0 were the
  static ones, so every timing statistic drawn from that member came from the
  wrong pairs. ⚠ The tool was written WITHOUT consulting this entry, whose
  status has said `factor-candidate` and whose header has recorded a consult
  miss since 2026-07-03. That is now twice. **The flat Mode-1 verdict cannot
  see this class at all** (it concatenates across play boundaries), so any
  future per-play or per-invocation instrument inherits it by construction —
  which is the argument for the Move-1 factoring rather than a fifth
  implementation.
  Two details are the difference between a fix and a new bug, both caught by
  controls and worth carrying into the factored form: try shifts in |shift|
  ORDER with a STRICT improvement test so 0 wins ties (otherwise a pair with
  no matching plays anywhere returns a confident -6), and fall back to 0 when
  the best score is zero matches.
  **Alignment is PER CHIP** on a multi-SID member (C28): a rebuild can be
  exact on both chips and still bucket one of them differently, because the
  two chips' work is emitted at very different points in the frame — measured
  on Bamse_Bert_2SID, chip 1's burst sits 3.6k-16.7k cycles after the play
  entry (p10..p90) against chip 0's ~400, so no single whole-member shift
  exists and 22% of plays read as mismatched.
- **Status:** factor-candidate (4× implementations; 5 occurrences; 2 recorded
  consult misses).
