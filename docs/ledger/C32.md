### C32 — orderlist state carries over the loop wrap: fold the state-closure unroll into a PHYSICAL stated form

**Problem class.** An engine's orderlist/track loops via a marker, and
engine STATE (transpose, sticky sector state — duration/instrument carry)
persists over the wrap. An extractor that walks the track therefore cannot
stop at one pass: the same physical entry decodes differently on the intro
pass (from init state) vs the steady loop (from carried state), so the walk
unrolls passes until `(wrap target, carried state)` repeats — and the USF
stores the unroll (2× the physical track for nearly every looping voice,
even when the passes are IDENTICAL, since the closure can only detect a
repeat by walking it). Fitted phase-model params (DMC's
`otrk_pad`/`otrk_period`/`otrk_rcmd`) then re-derive the original's track
byte-position counter, which off-table reads sonify (C11).

**PRESENTS:** a family's USF orderlists are ~2× the physical track with a
loop into the second copy; per-voice fitted scalar params model a byte
counter; a residue class exists where the fit fails (`otrk_legacy`).
Census tell: most members' two passes are byte-identical duplicates; the
genuinely-different tail splits into transpose-inheritance diffs (derivable)
and sticky-decode intro variants (content).

**Canonical solution (DMC v4, 2026-07-19).** Fold the walk output into the
physical form by DIRECT OBSERVATION — never by fitting:

1. Physical slots = walk entries up to the first byte-offset non-increase
   (B); assert `loop_to == B` and that the post-wrap entries align to
   physical slots by exact byte-offset identity (a contiguous suffix S..B-1).
2. Per-slot STATED transpose-command marks derived from offset deltas
   (gap 0 = no command byte → transpose must equal inherited — assert;
   gap k = command + k-1 dead extra bytes). Marks are the composer's
   notation (redundant re-statements included) — §8 arrangement, same class
   as V5's positioned markers.
3. Intro-pass decode variants: where the pass-0 pattern differs from the
   steady decode, carry BOTH (`entries[i]` = steady, `intro_entries[i]` =
   intro). Effective transposes of both passes re-derived from the marks
   (assert both against the walked ground truth).
4. The composer re-derives the full unrolled emission (intro pass + steady
   cycle) and the byte-position counter seeds from the notation; the fitted
   params dissolve.
5. **Fallback discipline:** any voice failing the fold's assertions keeps
   the ENTIRE old representation + params (never downgrade a member to an
   approximation path it wasn't on).

USF form: `orderlist stated: b[~i][*r][+c][!k][^d] loop@S` — see
`src/usf/grammar.lark` (normative) `ol_stated`.

**Gate:** carrier refactor — full-family golden byte-identity
(`tools/golden_sid_diff.py`), with the write-stream classifier for the
inert class.

**Bonus finding (warning):** the fitted-`rcmd` emission had a LATENT
OFF-BY-ONE on rho-shaped tracks (loop target ≠ slot 0): the model derived
the rcmd bit from pass-1 misalignment but the composer applied it to pass 0
too, shifting every pass-0 counter seed +1. Invisible wherever no off-table
read sonified those seeds (423/5401 members carried the wrong bytes
inertly). Direct observation is not just cleaner than fitting — fitting
against one alignment and emitting under another is exactly how coincidental
fits become latent bugs.

**Boundary.** The fold requires the universal 2-pass rho structure the DMC
walk produces (empirically 100% of probed voices; unfoldable walks — e.g.
mod-256 wrapped tracks — stay on the fallback).
A 3+-pass closure (never observed) would need intro-variant LISTS; do not
build that speculatively.

**REFINEMENT — the ENDLESS-TAIL admission (r128, 2026-07-28).** An
'endless'-sector self-loop (unterminated sector, 8-bit sectpos wrap: the
voice never fetches another track entry, otrk frozen forever) IS foldable
once the walk balances its offsets: the walk emits [.., lead, period] as
two entries at ONE track byte (equal `entry_offsets` — an observed track
fact; the pre-r128 imbalance len(offs)=n-1 was a plain bookkeeping bug that
forced every endless voice onto otrk_legacy, whose entry+1 approximation
drifts wherever transpose commands accumulate — Deprave_7_tune_3, flat
30139). The tail presents to the fold as a length-1 cycle at the last slot
whose intro (lead) differs from its steady (period) in STATED content —
admitted EXACTLY there (cycle length 1 + equal offsets + loop_to = tail
slot); the encoding-equivalence refusal below stands for every longer
cycle. Composer: a tail intro whose gid encodes differently emits
[gid_lead, otrk][gid_period, otrk] with the loop target at the steady
entry — lead once, period forever, the self-loop re-seeds the same frozen
otrk naturally; carried-only intro pairs dedup to one gid, so every other
member is byte-identical. Census: 32 f1 carriers, 27/28 prior FULLs held
(1 pre-existing palimpsest), no regressions. NB the `otrk_chg` fitted-param
alternative was REJECTED per this entry's own "observe, don't fit" — a
derivation rule chosen because it reproduces the data is the fitted-model
disease with an exactness alibi.

## Second occurrence — PATTERN-ROW sticky state (D6 piece 2, 2026-07-19/20)

The same class one level down: engine sticky state carried across
PATTERN boundaries (FC persisted note length; DMC sector-stream sticky
duration/instrument/volume) had been materialized into per-entry
EFFECTIVE pattern variants — FC's `(fc_id, init_len)` dedup key (probe:
+41% phantom pool duplication across 97% of members), FC's `loop@N
len=L` wrap-pickup annotation, and DMC's `~intro` decode variants
(probe: 10,343 slots, ~100% vol/instr carry). All three were ONE
phenomenon and dissolved into the same canonical shape:

- **Stated notation:** a NoteRow carries duration/instrument/`vol=`
  only where the source stream states the command (value presence = the
  byte fact); absent = inherit, across pattern boundaries and over the
  loop wrap. Leading inherited runs resolve from `init.voice_state`
  seeds (`dur_field` / `instr`), emitted only when consumed.
- **One shared resolution interpreter** (`src/usf/resolve.py`) consumed
  by BOTH composers (compose-time materialization feeding the existing
  encoders → byte-identity) and by Layer-3 validation.
- **Direct-observation + re-derivation assert:** the extract re-runs
  the shared resolver against the walk's decoded ground truth for both
  passes; ANY mismatch keeps the effective representation wholesale.
- **Discriminability guard:** a form the composer cannot structurally
  tell apart from the effective one (DMC: vol-only inheritance with no
  dur/instr marker) must NOT be emitted stated — fall back. Corollary
  (the Nocturno lesson): when an auxiliary byte-width shadow (sectpos)
  reads notation, keep it on ONE unambiguous source across stated AND
  fallback voices (the `*_cmd` flags stay on sonified members' stated
  rows, redundant with presence).

Gates: FC golden 2527/2528 byte-identical (1 predicted diff, the
deep-chain FULL member, re-verified) + DMC family-1 golden 5394/5394
byte-identical. Recoveries: the FC deep-chain wrap class (Man_of_Noise,
Love_Boat_Tune partial→FULL) — unrepresentable under the fitted
row-0-only fold.

**Boundary (piece 2, updated 2026-07-20):** the derived omission covers
the loop-wrap head AND mid-list `*r` repeat heads (extension landed
2026-07-20): a repeated entry whose head row inherits its duration and
whose pattern changes it internally is encoded with the head $8x
omitted, so the engine's runtime nootleng serves replays 2+
(`build_pattern_pool`; exact for play 1 too — its carry-in equals the
value the stamp would have held). VERDICT-INERT but not byte-inert: one
corpus carrier at landing (DEMOS/M-R/One.sid) was surfaced only by the
GOLDEN byte-identity gate (2529/2530 identical, the 1 diff), NOT by the
verdict — old and new both verify FULL with the identical play stream
(the omit-vs-stamp divergence on replays 2+ falls past songlength).
Lesson: the byte-identity gate catches past-window latents the FULL
verdict cannot. RESIDUAL corner,
shared by BOTH omission paths, corpus-unhit: the omitted-head encoding
delta-encodes MATERIALIZED values, so a STATED row inside the pattern
whose value coincides with the play-1 head value (only inherited rows
between) emits no $8x and would fail to re-anchor later passes/replays
— closing it needs statedness-aware forced-$8x emission in
`encode_pattern`; extend there if a member surfaces.

**BOUNDARY — an intro/loop variant pair is foldable ONLY when
encoding-equivalent (2026-07-23, r100).** The composer's stated encoding
plays ONE pattern per physical slot on every pass, so the fold may collapse
an intro/loop variant pair only when both encode identically (differ solely
in carried instr/vol, which the stated encoding erases). A pair differing
in STATED content or in duration (always carried in the event) cannot share
a slot — `_fold_stated_orderlist._stated_equal` REFUSES and the legacy
unrolled representation carries the member. Surfaced by C34's DMC track
quirk (Dance: the mid-sector loop re-entry skips the sector's leading
command bytes, so the loop variant INHERITS what the intro variant STATES);
the same refusal cured the Rayden 2SIDs' latent carried-duration collapse
(the old fold played the intro pass's durations on every loop pass).

**REFINEMENT — the seed VALUE must be observed, never assumed cleared
(2026-07-24, r113 Christmas_Aches_tune_2).** "Leading inherited runs
resolve from `init.voice_state` seeds" is only correct if the seed is the
ENGINE'S init value. The DMC walk seeded sticky instrument = 0 and the
composer hardcoded `curinst,x` = 0 — but the canon player's init clears
$1718-$179D and NOT the per-voice current-instrument number $1015-$1017,
so a voice that note-inits before any $6x command plays the WORK-FILE
LEFTOVER instrument (same leftover family as idle_notes / durrel_init /
slide_phase; Christmas_Aches V2: leftover $01 = the SR-$CB drum whose fx
also fires the filter program — first divergence read as an instrument-
content bug, was an init-seed bug). Fix shape: read the leftover at
`_eventdriven_addrs(cfg)` INS (curnote+3, relocation/compilation-aware),
re-walk seeded ONLY when a note row precedes the first $6x command
(consumption-gated: zero churn for the corpus-dominant dead-seed case)
and the byte is a plausible instrument number (<$20 — a wilder leftover
would need the note-init's exact ADC-chain wrap emulated; refuse, stays
partial); emit `init { voice N { instr: i<seed+1> } }`; the composer's
`curinst,x` priming reads an `icinst` slot table gated to the historical
constant form when every slot is 0 (byte identity). For every sticky
channel with an init seed, ask: does the engine's init actually CLEAR
this state, or is the seed a leftover to read?
