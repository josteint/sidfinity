### C32 — orderlist state carries over the loop wrap: fold the state-closure unroll into a PHYSICAL stated form

**Problem class.** An engine's orderlist/track loops via a marker, and
engine STATE (transpose, sticky sector state — duration/instrument carry)
persists over the wrap. An extractor that walks the track therefore cannot
stop at one pass: the same physical entry decodes differently on the intro
pass (from init state) vs the steady loop (from carried state), so the walk
unrolls passes until `(wrap target, carried state)` repeats — and the USF
stores the unroll (2× the physical track for nearly every looping voice,
even when the passes are IDENTICAL, since the closure can only detect a
repeat by walking it). Fitted phase-model params (DMC's
`otrk_pad`/`otrk_period`/`otrk_rcmd`) then re-derive the original's track
byte-position counter, which off-table reads sonify (C11).

**PRESENTS:** a family's USF orderlists are ~2× the physical track with a
loop into the second copy; per-voice fitted scalar params model a byte
counter; a residue class exists where the fit fails (`otrk_legacy`).
Census tell: most members' two passes are byte-identical duplicates; the
genuinely-different tail splits into transpose-inheritance diffs (derivable)
and sticky-decode intro variants (content).

**Canonical solution (DMC v4, 2026-07-19).** Fold the walk output into the
physical form by DIRECT OBSERVATION — never by fitting:

1. Physical slots = walk entries up to the first byte-offset non-increase
   (B); assert `loop_to == B` and that the post-wrap entries align to
   physical slots by exact byte-offset identity (a contiguous suffix S..B-1).
2. Per-slot STATED transpose-command marks derived from offset deltas
   (gap 0 = no command byte → transpose must equal inherited — assert;
   gap k = command + k-1 dead extra bytes). Marks are the composer's
   notation (redundant re-statements included) — §8 arrangement, same class
   as V5's positioned markers.
3. Intro-pass decode variants: where the pass-0 pattern differs from the
   steady decode, carry BOTH (`entries[i]` = steady, `intro_entries[i]` =
   intro). Effective transposes of both passes re-derived from the marks
   (assert both against the walked ground truth).
4. The composer re-derives the full unrolled emission (intro pass + steady
   cycle) and the byte-position counter seeds from the notation; the fitted
   params dissolve.
5. **Fallback discipline:** any voice failing the fold's assertions keeps
   the ENTIRE old representation + params (never downgrade a member to an
   approximation path it wasn't on).

USF form: `orderlist stated: b[~i][*r][+c][!k][^d] loop@S` — see
`src/usf/grammar.lark` (normative) `ol_stated`.

**Gate:** carrier refactor — full-family golden byte-identity
(`tools/golden_sid_diff.py`), with the write-stream classifier for the
inert class.

**Bonus finding (warning):** the fitted-`rcmd` emission had a LATENT
OFF-BY-ONE on rho-shaped tracks (loop target ≠ slot 0): the model derived
the rcmd bit from pass-1 misalignment but the composer applied it to pass 0
too, shifting every pass-0 counter seed +1. Invisible wherever no off-table
read sonified those seeds (423/5401 members carried the wrong bytes
inertly). Direct observation is not just cleaner than fitting — fitting
against one alignment and emitting under another is exactly how coincidental
fits become latent bugs.

**Boundary.** The fold requires the universal 2-pass rho structure the DMC
walk produces (empirically 100% of probed voices; unfoldable walks — e.g.
'endless'-sector self-loops, mod-256 wrapped tracks — stay on the fallback).
A 3+-pass closure (never observed) would need intro-variant LISTS; do not
build that speculatively.
