### C23 — A play-phase TOKEN hides a per-member behavioural ambiguity (2-frame note-start)
- **The problem class:** a C18 play-phase schedule token (`P_F123`) is treated
  as fully specifying what each call does, but the SAME token maps to TWO
  distinct play-routine behaviours across members. DMC F phase: some members'
  play-routine enters the F call at the note-init check (`$11F9` → note-init on
  the F call = IMMEDIATE note-start), others enter PAST it (`$1591` wave-step),
  so a note fetched on a P call only ARMS on the F call (wave-step only, ADSR
  held at the `$0F0F` hard-restart leftover) and note-inits on the NEXT P call
  = a 2-FRAME note-start. The blanket model (F → frame_entry) is right for the
  majority and wrong for the deferring class.
- **TELL / how it presents:** you fix the minority class and it REGRESSES
  currently-FULL members carrying the SAME token (Words and F.A.K.E-Intro are
  both `P_F123`, opposite behaviour). The regression is the signal that the
  token is INCOMPLETE, NOT that the fix is wrong (the round-23 lesson: a correct
  fix that regresses ⇒ the regressed members are FULL through a blanket/
  suboptimal model; reimplement to serve BOTH). Sibling of C22 (an encoding
  that renders two ops identically) — here the "encoding" is the phase token.
- **Canonical fix:** do NOT pick one behaviour or add a schedule-string
  heuristic — the distinction is not derivable from the token OR the editor
  setting (Words/F.A.K.E are both `P_F123` AND both 1.82 calls/frame). OBSERVE
  the distinguishing behaviour per member (C18: observe, don't parse) from the
  WRITE FOOTPRINT (reloc-invariant, no PCs): the opening note-start's first
  freq/ctrl re-emit after a voice's HR call (ctrl=`$08`, AD=SR=`$0F`) is the
  note-init IFF it also writes AD/SR; freq/ctrl with NO AD/SR = the arm ⇒
  deferred. Emit a per-member param; the one composer routes on it (F →
  wavestep when deferred, frame_entry otherwise). **Regression-safe by
  construction:** note-init ALWAYS carries AD/SR, so the "deferred" verdict has
  no false positive — the immediate majority is provably untouched.
- **METHODOLOGY:** measure the candidate discriminator (multispeed factor,
  schedule string) against BOTH the fixed set and the regressed set BEFORE
  designing the fix — if they overlap, it's a per-member observable, not a
  derived rule. Focus the verdict on FIRST-DIVERGENCE resolution, not FULL: the
  fix resolved the note-start for all 15 cluster members (0 regr) even though
  only 4 reached FULL (the other 11 advanced to a separate freq-drift blocker).
- **Status:** logged (DMC family-1, 2026-07-05: +4 FULL [2_Speed / Voices /
  Canned / Compotune], 0 regressions across all 56 currently-FULL F-token
  members + full `tools/regression.py`). Commit 1a632fe.

- **2nd occurrence (round 123, 2026-07-27) — the rule generalises past
  play-phase tokens to RE-ASSEMBLED BUILD SEMANTICS:** Redable_Rain
  (Heinmueck's re-assembled DMC build, dataflow path, base $1000 generated
  by init — not in the file image). Its note-init routine RTSes before the
  wave step (init frame = SR+AD only, ctrl order SR-first; the note's first
  freq/PW/ctrl land on the NEXT play), and its hard-restart prep writes
  ctrl $08 THEN $09 before the $0F0F. Both are per-member build semantics
  that no static canon-offset probe can address on a re-assembled layout —
  so OBSERVE the write-footprint from the ORIGINAL's per-IRQ writelog
  (libsidplayfp ground truth, Trap-C-free): `factory._noteinit_defer_probe`
  classifies each play() chunk per voice — melodic init chunks (AD+SR pair,
  not $0F0F prep / $00,$00 hold-clear, not the cymbal burst shape ctrl=$81
  +freq, which both variants emit on the init frame) must ALL lack a ctrl
  write (>= 8 seen) ⇒ `noteinit_defer_wave='1'` (composer: ni_wave RTS);
  prep chunks (AD=SR=$0F) must ALL show the exact [$08,$09] ctrl sequence
  ⇒ `hr_prep_gate='1'` (composer: prep writes TEST then TEST|GATE). Both
  classifiers are all-or-nothing so a canon member cannot false-fire; the
  observation is gated to DATAFLOW-path members (canon members are proven
  canon by the masked compare) and skipped under a C18 phase wrapper
  (split init writes could mimic the footprint). Redable_Rain partial
  0.0% → FULL 122680.
- **2026-08-01 refinement (round 168, Wodnik/Akademia) — the
  `noteinit_defer_wave` classifier's STRICT all-or-nothing gate is too brittle
  for HIGH-MULTISPEED CIA members.** The gate required EVERY melodic init chunk
  to lack a ctrl write (`with_ctrl == 0`). But on a fast CIA tune (Akademia is
  2×+ multispeed) two consecutive play()s occasionally land in ONE
  `writelog_per_irq_capture` bucket, MERGING a deferred init's AD/SR with the
  NEXT play()'s wave-landing ctrl into one chunk — a false canon-init the strict
  gate reads as a disqualifier. Akademia: 46/47 chunks pure-defer, 1 merged
  bucket (its per-IRQ frame carries ~2× the writes) → rejected, built canon
  (partial), even though forcing `noteinit_defer_wave` gives 100% FULL. Fix:
  relax to `with_ctrl * 5 < inits` (< 20% carry ctrl). **The two populations are
  cleanly separated with enormous margin** (measured over 30 members: canon
  members cluster at 95-100% carry-ctrl — a canon init ALWAYS has AD/SR + ctrl
  same-play; defer members at 0-2%; the 20% threshold sits in the empty gap).
  **0-regression is structural, not just empirical:** a member built correctly
  WITHOUT defer_wave has canon same-play inits (ratio ~100%), so it can NEVER
  fall in the low-ratio flip band — only defer-shaped PARTIALS flip. Verified:
  across the portfolio + wedge-FULLs + existing defer carriers + a random
  family-1 sample, Akademia is the ONLY flip (→ FULL 151466/151466), every
  other member's classification is unchanged (byte-identical build). NOTE the
  strict `==0` was itself wrong for any defer member with even one collision —
  the tolerance is the correct model, not a loosening.
- **2026-08-01 refinement 2 (round 169, Wodnik/CH2) — the `hr_prep_gate`
  classifier had the IDENTICAL brittleness on the SAME per-IRQ bucketing
  collision, and needed TWO complementary tolerances.** The gate required EVERY
  prep chunk (AD=SR=$0F) to show the EXACT `[$08,$09]` ctrl list
  (`preps_gate9 == preps`). A merged bucket PREPENDS the prior play()'s note
  ctrl → `[$41,$08,$09]` (or `[$10,$08,$09]`), which `== [$08,$09]` misreads as
  canon. Unlike the defer_wave collision (per-chunk INDISTINGUISHABLE from a
  canon init ⇒ ratio only), the hr_prep collision is per-chunk RECOVERABLE — the
  `[$08,$09]` SUBSEQUENCE survives the prepend. Fix: (1) test the `[$08,$09]`
  SUBSEQUENCE not equality (recovers the merge collisions — CH2 131/138 → 138,
  Szach 19/20 → 20); (2) relax the aggregate to `preps_gate9 * 5 > preps * 4`
  (> 80%) to also absorb the rare bucket that SPLITS the $08 and $09 into two
  chunks (Czad 178/179). Same clean separation and structural 0-regression as
  defer_wave: canon preps write $08 ALONE (0% show `[$08,$09]`), so a
  FULL-without-hr_prep member (its orig writes $08 alone, else the missing $09
  makes it partial) can never reach the > 80% band. Verified over the whole
  Wodnik family + canon controls: only CH2/Szach/Czad flip (all → FULL:
  176680 / 183194 / 60743), every existing carrier + canon member unchanged.
  +3 FULL.
