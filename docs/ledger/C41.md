### C41 — gate an extract that has NO composer yet by PREDICTING the write stream

**Status:** logged (1×, Rayden_Digi 2026-08-31) · **Class:** methodology

## Problem class

A new family's extract lands long before its composer. Until the composer
exists there is no rebuild, so the project's verdict machinery
(`compare_instruction_stream`, `verify_all`, the family batch) has nothing
to judge — and the extract sits unverified for however many sessions the
composer takes. That is exactly the window in which a plausible-but-wrong
model gets built on top of: every later divergence is then debugged against
an extract nobody ever checked.

The temptation is to call the extract "done" because it produces
well-formed output, or to gate it on a self-consistency property (it
round-trips, it parses, its numbers look sane). Neither touches the
original.

## Canonical solution

**If the model can PREDICT an observable of the original, gate on that.**
Many extracted models can: a score model says which sample plays when, an
instrument model says what a program emits, a pattern model says which
notes land in which frame. Compare the prediction against
`siddump --writelog` — the same ground truth the real verdict uses, just
consumed a stage earlier.

The Rayden_Digi form (`pipelines/rayden_digi/verify_score.py`), which
generalises:

1. **Predict the stream the model implies.** There, each score event
   re-triggers a sample, so the measured `$D418` stream is the
   concatenation of per-event prefixes of each sample's nibble stream.
2. **Walk the measured stream with a CURSOR, not a search.** Hold the
   current event's model position; advance while it explains the next
   write. Where it stops is a BREAK — a real event, not noise.
3. **Every break must be explained by a NAMED engine behaviour**, and each
   one is a fact you had to learn about the player: a re-trigger phase, an
   interloper write from another routine, a stale byte. Enumerate them;
   never add a generic "skip up to N mismatches" tolerance, which converts
   the gate into a similarity score.
4. **Split the verdict into a CONTENT and a TIMING check.** Content proves
   the values and their order (pointers, tables, terminator, packing,
   sequence). Timing proves the quantities content is blind to (durations,
   rates) by fitting ONE global constant across all segments and reporting
   the residual SPREAD. Two checks that can fail separately are worth far
   more than one combined score. Keep them independent if you can — and
   when you cannot (see the full-span section below, where content needs
   the timing constant to place ambiguous boundaries), say by how much
   rather than letting one silently assume the other.
5. **Report the residue, and refuse to call an ambiguous alignment a
   pass.** Count the writes that went through each escape hatch. Where a
   member's content is explainable but its event boundaries are not pinned
   down (Rayden's Embarassed_Emotions: a 1-byte constant sample plus a
   per-frame idle insertion), the timing check has no power and the verdict
   must say so — `timing_ok` separate from `ok` — rather than inheriting
   content's pass.

## Why it is worth the effort

It found things the eventual composer would have had to find anyway, but
cheaply and with the cause visible: the NMI-vector re-trigger phase, the
per-frame idle-level write, that the NMI period is `latch+1` (the model
lands on exactly 2.0025 ticks/frame with `+1` and misses with `latch`), and
that one member's timing is not determined by its stream. None of those are
derivable from the file image; all of them are composer requirements.

It also bounds the blast radius of the NEXT session: when the composer's
first build diverges, the score model is already known-good, so the
divergence is in the composer.

## Boundaries

- Needs an observable the model determines. A model that only describes
  STRUCTURE (which bytes are a pattern table) predicts nothing and gets no
  gate this way — use the byte-level round-trip check instead
  (`pattern_stream_verify.py`'s shape).
- The absolute scale of a fitted rate can be off without the model being
  wrong: at Spelling_Around's 67-cycle NMI period, VIC badlines swallow
  ~9% of the interrupts and the fitted rate reads low while every residual
  stays under 0.35%. Judge the SPREAD; treat the scale as a sanity check.
- It is not a substitute for the real verdict. It proves the extract, never
  the rebuild — the composer still has to produce the stream.

## ⚠ MEASURE OVER THE FULL SPAN — a partial capture looks CLEAN, not truncated

At a 60-second capture this gate reported 100% on three members that the
same code actually lost at 28-65% of their songs. A looping score's prefix
matches perfectly, so a short window produces a confident, well-formed,
WRONG pass — the same shape as the project's existing digi rule (a short
capture landing in an idle intro reports a constant value and reads as a
stuck master volume), reached from the opposite direction.

The cause there is worth carrying: the alignment's one genuinely ambiguous
case is a re-trigger INSIDE a long constant run of the outgoing sample,
where the cursor sails past the true boundary and every candidate near the
observed break is wrong. The cure is to run the alignment TWICE — fit the
timing constant from what aligns unambiguously, then use it to place the
hidden onsets, keeping pass 2 only if it explains more. That costs the
INDEPENDENCE of the two checks, so report how many onsets needed the prior
rather than letting the content result quietly assume the timing one.
