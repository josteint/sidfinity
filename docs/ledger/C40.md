### C40 — cycle-strict rebuild of a SELF-DRIVEN member (Mode-2 timing diagnosis)

**Problem class.** A member whose original is SELF-DRIVEN (RSID
play=$0000: init installs its own IRQ/NMI plumbing; the host idles in
psiddrv between interrupts) must verify CYCLE-STRICT (core tenet
Mode 2 — digi, where write timing IS the signal). The entire stream
timing is then determined by the rebuild's own generated code, and the
class of divergence is CYCLE-PHASE, not content: identical `(reg,val)`
sequences at shifted cycles, or content shifts caused by timing
truncating a sample differently.

**Canonical solution** (built on Digi-Organizer, 2026-08-29; 21/39
standalone FULL, 0 partial — `pipelines/digi_organizer/`):

⚠⚠ **POINTS 1 AND 2 WERE WRONG AS ORIGINALLY WRITTEN (corrected
2026-08-30 on the owner's challenge). They are kept here, corrected,
because the mistake is instructive and the next Mode-2 family will be
tempted by it.** The original text said "mirror instruction SHAPES"
and prescribed a driver CLASS REGISTRY. That is a slide, in three
steps, from a true premise to a false conclusion: the verdict requires
the same CYCLE SCHEDULE → so mirror the instruction shapes → so keep
one hand-written emitter per observed shape. Only the first step is
forced. Producing the same schedule does NOT require producing it the
same way, and the Core Tenet warns against exactly this move: *"If you
find yourself reading a long disasm and asking 'how do I mirror this
structure,' stop and ask 'what writes does this produce'."* The
registry that grew out of it reached 14 entries, six of them with a
single carrier, and it is a §7 violation in the plainest terms — a
library held by the composer that the USF indexes into by name.

1. **Match the cycle SCHEDULE; own the code.** Mirroring instruction
   shapes is one way to get the schedule and the laziest one. What the
   verdict actually constrains is: the same writes at the same cycles.
   Placement is free page-granularly (see 3d); the schedule is a small
   set of NUMBERS you can hit with your own code plus filler (NOP=2 and
   a 3-cycle op make every count >= 2 reachable).
2. **Parametrize the driver; a CLASS REGISTRY is a smell, not a
   solution.** ✅ DONE for Digi-Organizer (2026-08-30): the 14 emitter
   templates AND the 14 shape probes are gone, replaced by a generic
   instruction walk that MEASURES each driver plus one emitter that
   synthesises code for what was measured. Three things the doing
   taught, none of which the design predicted:
   - **The fact is a SCHEDULE, not a total.** Matching the cycle count
     to the core is not sufficient: Heavy-Beat's every offset agreed
     except the last, where the original reused a register (`INX`) to
     write $D019 at cycle 53 while a reload put ours at 55 — and that
     alone shifted the whole NMI grid. Record `token@cycle` and pin
     each bus access to its measured cycle.
   - **The emitter must therefore be a small SCHEDULER**, not a
     code generator: pin the stores, then place the loads in the gaps —
     hoisting one into an earlier gap and a second register when the
     slot before a store is already full, which is what originals do
     when they issue several loads and then several stores back to back.
   - **Free vs observable splits on the interrupt mask.** The init runs
     under SEI, so nothing can see its shape and only its schedule and
     final state matter. The wrapper and any busy/delay loop run with
     NMIs live, so THEIR instruction boundaries are observable — filler
     there must use the fewest longest instructions (two NOPs are not
     one 4-cycle BIT), and a delay loop is reproduced by its period.
   The pay-off beyond the principle: an unfamiliar driver is now DECODED
   rather than refused, which a catalogue can never do.
 MEASURED on Digi-Organizer's 39 members (2026-08-30),
   after the registry had already reached 14 classes: a generic
   instruction walk from the init vector reaches the core on 39/39 with
   NO pattern matching, and every class reduces to
   (ordered environment writes, cycles-to-core, core entry, tail form,
   wrapper shape). The env writes come from a 13-address vocabulary
   ($01, the two vector pairs, $D011/12/19/1A/20/21, $DC0D/0E, $DD0D);
   cycles-to-core spans 6..88; and the per-class cycle VARIANCE was
   fully explained by the existing sub-shape flags (nmi_first 25-vs-27
   is the SEI flag, xreg 67-vs-71 the BIT filler). The wrappers collapse
   just as hard — 8 of 14 are structurally identical (save A/X/Y, ack,
   tick, restore, RTI), and all four ack forms (asl/inc/dec/lda+sta on
   $D019) cost exactly 6 cycles.
   So: DECODE those facts generically and emit ONE universal driver from
   them. A generic decoder also ACCEPTS new members instead of refusing
   them, which the registry cannot. Naming classes by SHAPE rather than
   by author (the original advice) mitigates nothing — the §8 test is
   whether the composer's choice of which 6502 to emit depends on USF
   content, and with a registry it does, whatever the values are called.
3. **The diagnosis table** — measured signatures → causes:
   - constant per-write cycle delta, content identical ⇒ the IDLE-LOOP
     PHASE vs the interrupt grid differs. A single-byte code
     difference AFTER the timer start (an RTS vs NOP/CLI tail)
     re-phases the idle loop and shifts interrupt LATENCY by a
     constant. Mirror the tail (`digi_core_tail`).
   - playback starts late/early by ~N interrupt periods, then tracks ⇒
     the TIMER GRID ORIGIN differs: the pre-first-trigger latch (the
     grid spacing until the first per-sample latch write) or the
     init-entry→timer-start cycle count. Carry the probed base latch
     (`digi_base_latch`) — never derive it from the sample latches
     (min(rate) coincided on the first member; the second exposed it).
   - one extra/missing value at a sample SWITCH, then re-aligned ⇒ a
     phase/grid mismatch truncated the outgoing sample at a different
     interrupt slot — fix the grid, not the content.
   - rebuild silent while orig plays ⇒ ENVIRONMENT divergence: measure
     the effective port/vectors on BOTH sides with
     `--peek-post-init 0001,0314-0315,FFFE-FFFF` before theorizing
     (Digi-Organizer's Morton shape sets $01 in a CORE-ENTRY stub its
     driver never reaches on other members). ⚠ SECOND CAUSE, and check
     it FIRST because it is one field: the HOST REFUSED THE FILE. RSID
     validation (`SidTuneBase::checkCompatibility`) rejects a load
     address below $07E8 or an init address in $A000-$BFFF / $D000-$FFFF
     outright — no diagnostic reaches the write stream, the capture is
     simply empty. Any composer free to choose its own layout has to
     encode those two rules, not discover them.
   - content-perfect at every horizon but the whole stream runs at a
     constant RATE RATIO (5/6, 6/5) ⇒ the PSID CLOCK flag. A member
     whose tick is a raster IRQ runs at the FRAME rate, so an NTSC
     original is a 60 Hz stream and a PAL-defaulted rebuild is 50 Hz —
     every value right, every cycle stretched. Parse the header flags,
     carry them in the typed `PsidMeta.clock`/`sid`, and derive the
     rebuilt header from them. This presents almost exactly like the
     3b first-tick phase slip below and is NOT that: a slip is a
     one-time offset, this is a slope. (Digi-Organizer's two Sphere
     members sat parked for a round as "extensively measured
     first-tick phase" before the header was looked at — the general
     discipline is [[feedback_header_flags_audible]].)
3b. **Refinements from the driver-zoo round (2026-08-29 evening):**
   - PAGE-ALIGN generated loops: a taken branch crossing a page costs
     +1 cycle PER ITERATION — the poke_stub delay loop crossing a page
     shifted the whole stream by exactly its 11 outer iterations.
     Since the originals are page-local, page-align the emitted driver.
   - A shifted-but-perfect-prefix stream at EVERY horizon (content
     never diverges, rebuild simply lags wall time) ⇒ the FIRST tick's
     phase slipped once (e.g. the first raster IRQ against an env
     $D012 latch neither side writes) and every row inherited the
     shift. Diagnose with wall-frame indices of burst starts
     (`grep -n '|W:'`), not per-frame cycles — compacted writes-only
     frame counts are NOT a rate measurement.
   - A runtime SPEED POKE (`LDA src / STA <tick immediate>`) makes the
     poked value the musical TEMPO and the image byte only the
     first-row seed (typed `speed_ctr_init`); the poke value derives
     from tempo — never carry it as its own param.

3d. **Layout is free — but only PAGE-GRANULARLY, and the mirrored code
   can encode layout invariants** (round 4, Digi-Organizer). A member
   whose PCM does not fit the composer's habitual memory map forces the
   player block to move. Moving it as a WHOLE by a multiple of $100 is
   cycle-neutral by construction: every 6502 timing quantity that is
   not fixed — taken-branch page crossings, indexed-read page crossings,
   the SMC pointer walk — depends only on LOW bytes. Moving it by
   anything else, or moving part of it, is not.
   ⚠ Then check what the MIRRORED init reads as DATA. Byte-saving
   originals reuse whatever is already in a register, and a page byte
   is a register value: Digi-Organizer's core init seeds the pattern
   REPEAT counter with `sty` reusing `Y = >idle_nmi`, which is only
   NEGATIVE (the "first order fetch must latch" flag) because the
   canonical player sits at $9000. Relocated to $0800 the build was
   clean, verified, and played every pattern ten times instead of
   twice. Under Mode 2 you cannot repair this with an extra load — the
   init's cycle count IS the interrupt-grid phase — so the invariant
   binds the LAYOUT. Assert it from the assembled labels rather than
   trusting the placement policy. (Its sibling: the NMI vector swap
   writes only the LOW byte, so all handlers must share one page.)
   Corollary for the PCM itself: when an original's sample table carves
   several windows out of ONE recording and the USF stores each window
   as its own sidecar, the sharing must be recovered CONTENT-ADDRESSEDLY
   at placement — and in BOTH directions, since which window was seen
   first is an artifact of sidecar naming. Containment alone left
   Digibeatz_2 needing 429 pages for 216 pages of audio.
   Also: a PRE-core-init speed poke is the mirror of 3b's post-init one.
   Poked before anything reads it, it replaces the image byte for the
   init seed AND every steady reload, so the file's byte is editor
   residue; poked after, the image byte really is the first row's
   duration. Same instruction shape, opposite conclusion — read the
   ORDER, not the shape.

3e. **A mirrored CLAMP is a BRANCH, so the DATA FORM is a cycle fact**
   (round 4, Digi-Organizer — it closed the family's last three
   partials at once). ⚠ THIS IS LEDGER C22's CLASS, encoder side — see
   C22 occurrence (4). It was solved here from scratch, by pc-tracing,
   because nobody looked C22 up first; the lookup would have named the
   remedy immediately (emit the distinguishing fact ALWAYS, decide on
   its PRESENCE). Engines routinely normalise sloppy table data at
   runtime: Digi-Organizer's trigger reads a sample's start and end
   page and does `CMP end / BCC ok / CLC / ADC #$01` — a row whose end
   is <= its start means "one page". Two rows can therefore describe
   the SAME sample through DIFFERENT arithmetic, and a composer that
   regenerates data from musical content will pick one form for both.
   The values agree; the branch does not, and under Mode 2 those 2
   cycles re-phase every interrupt that follows.
   So: whenever the mirrored code CLAMPS, NORMALISES or DEFAULTS a data
   value, the pre-clamp form is part of the cycle skeleton and has to
   survive to the composer. It is not musical (the audio is identical,
   so the C19 33rd-occurrence test passes) — it belongs in the params
   bag as a registered mechanism knob, never on the musical object.
   ⚠ And do NOT assume it is derivable from the post-clamp value: the
   corpus carried BOTH forms at one page (19 normal, 5 degenerate), so
   "one page ⇒ degenerate" would have traded three partials for two
   regressions — which is exactly what the first blanket experiment
   measured before the per-instrument carrier replaced it.
   TELL, and it is a subtle one: the writelog is content-identical
   while the inter-write deltas alternate with the SAME MEAN but a
   DIFFERENT SPLIT (orig 74/88, rebuild 77/85 — the relative offset
   between the two NMI handlers' writes). Localize by pc-tracing both
   sides and diffing CYCLES, not PCs (the PCs differ everywhere by the
   composer's own layout). ⚠ Convert the frame index first: a
   `writelog_capture` frame is COMPACTED (writes-only) and a
   `--pc-trace` frame is raw, so the naive index traces the wrong
   window and reports perfect lockstep (C36).

3c. **The KERNAL-path environment family** (round 3, Digi-Organizer):
   a member that keeps the KERNAL banked in (port $36) routes its IRQ
   via the $0314 RAM vector (wrapper exits `JMP $EA31`/`$EA81` — the
   KERNAL entry does the pushes) and its CORE is a variant with **all
   NINE NMI vector-swap operands re-pointed at $0318/$0319** (the
   KERNAL NMI RAM vector) — probe ONE site, REQUIRE all-site
   consistency, substitute globally (`digi_nmi_vec`). Its cousin banks
   the ROM "out" the hard way: a core-entry stub that COPIES
   $E000-$FFFF under itself then DECs the port (~131k pre-timer
   cycles, all grid phase — mirror the loop exactly). TELL for the
   whole family: rebuild silent while orig plays → peek
   $0001/$0314-15/$0318-19/$FFFA-FB on BOTH sides; the orig's $0318
   holding a core handler address is the giveaway.

4. **Reachability-gate static probes.** The same pre-init stub sits
   UNREACHED (editor leftover) in members whose driver enters the core
   elsewhere — a C19-style static probe must fire only when the entry
   path actually reaches the probed site, else a leftover false-trips
   a refusal (or worse, a wrong knob).
5. **Denominator warning.** A digi family's sidid carriers largely
   PAIR with other engines' members (Digi-Organizer: 131 claimed, 39
   standalone); the family store covers only the standalone form until
   the heterogeneous path exists. State coverage as x/standalone AND
   x/claimed, and give the family a claimed-vs-batched gap check at
   closeout (the `route.py --gaps` lesson).

**Boundary.** Mode-1 (tracker) members need none of this — flat
compare absorbs cycle position (Trap B). And the TRICHOTOMY's
universal-init verdict does not apply under Mode 2: init write CYCLES
are signal, so init is mirrored per class, while the trichotomy's
CATEGORIES still route the content (master_vol prime → init.sid;
temporal facts → environment-category params).

**A non-digi cousin of 3d, worth stating once.** The unbounded walk
this family's sequencer does over its orderlist has no terminator in
some members, so the walk runs off the authored data into the member's
own PLAYER CODE and reads it as pattern/repeat pairs (Digi_Zak_2: the
driver's `SEI / LDA #$35` decoded as "pattern 120, repeat 41", with
garbage sample-table rows behind it that refused the build). Memory at
or after a LOCATED code/table structure cannot hold authored entries —
the player would be corrupt — so the walk stops there and the song
simply ends. The engine would happily sonify its own code if left
running; that is not musical content (C7), and the measurement that
settles it is where the original's own order position actually reaches
over the ratified window.
