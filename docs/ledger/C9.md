### C9 — A runtime parameter py65 can't read → measure it from the writelog
- **Canonical:** when a build-time parameter is set by code py65 can't execute
  (init hangs, the value is programmed in an IRQ handler, or an unsupported
  opcode aborts the trace), DON'T reject the member — MEASURE the parameter from
  the GROUND-TRUTH writelog (libsidplayfp runs the real CPU). Sibling of C4
  (localize a divergence via memwatch); both replace a py65 limitation with a
  libsidplayfp observation.
- **Status:** recurring (DMC v4 CIA multispeed rate 2026-06-25; single-speed
  DEFAULT latch 2026-07-06; the multi-SID path never measured it 2026-07-21;
  the same path defaulted EVERY other knob 2026-07-21).
- **3rd occurrence (2026-07-21) — A SECOND BUILD PATH SILENTLY DEFAULTED THE
  RATE.** `_config_at_base` (the multi-SID sub-player constructor) never set
  `cia_period`, and `build_dmc_2sid_sid` never passed `speed=` to the header —
  so EVERY multispeed multi-SID member built as vblank. Invisible while the
  only carriers were vblank (Nice_Dream, Bamse); it surfaced the moment the 5
  CIA-timed Rayden members were detected. **TELL: a per-chip EXACT PREFIX at
  ~1/N of the original's length, with NO content divergence** — the rebuild
  plays the right notes at the wrong speed. Distinguish from C25 (a rate DRIFT
  of ~0.5% from cycle creep): this is a clean integer factor. Compounding
  cause: a **C18 phase schedule DIVIDES the timer rate** — latch $2663 (100 Hz)
  with a period-2 `P_F123` and $1331 (200 Hz) with a period-4 schedule BOTH
  give a 50 Hz music tick, so the schedule period and the multispeed factor
  must be read together (a member whose phase INC is wedged inert, Mc_Dieter,
  is a genuine 100 Hz tune). LESSON: when a parameter is measured in one build
  path, grep for the OTHER constructors of the same config — a defaulted
  `cia_period=0` is silent until a carrier reaches that path. +4 FULL
  (Mythig, Physician_Remake, Leprechaun_Boot_V2, DSR-FLT_Cracktroh).
- **4th occurrence (2026-07-21) — THE STRUCTURAL CURE: fix the CONSTRUCTOR,
  not the knob.** The 3rd occurrence patched ONE defaulted parameter
  (`cia_period`) in the second build path; the path itself still hand-rolled
  its config, so EVERY other probed knob stayed at its default. The next
  member to need one (`track_loop_target`) failed the same way — and, unlike
  a rate error, silently: a wrong loop target replays the wrong SECTION of
  the song, which reads as a deep content divergence (a wrong-instrument
  note), not as plumbing. LESSON: when you find a second constructor that
  defaults a probed parameter, do not enumerate the knobs — ask whether the
  second path can RUN the first. It usually can, because "the same player,
  just not owning the vectors" is already modelled (here
  `_build_via_canon(base_override=)`, built for C31 compilations). Keep the
  hand-rolled config as a FALLBACK so nothing regresses to unsupported, and
  have the fallback run whatever standalone probes it can. TELL that a
  constructor is under-probed: its config literal lists only addresses —
  no `extra_params`, no probe calls.
- **Boundary:** works when the parameter is OBSERVABLE in the write timing /
  memory. CIA multispeed rate: count play()s per PAL frame from
  `--writelog-per-irq --per-irq-debug` (`nentries`/frame, `base`=abs PHI1
  clock), round N to the integer factor, latch = 19656/N − 1 (the exact
  canonical $2663=2x / $1331=4x). The rounding makes it robust (N within 0.01).
- **NOTE — the SINGLE-SPEED CIA default latch (2026-07-06, Phobos/Crazy_Mix
  +3 FULL):** a PSID speed-bit tune whose init programs NO timer is still a
  CIA tune — it runs at the PSID environment's DEFAULT latch $4025 (16422
  cycles, ~60 Hz). The old "no readable latch → single-speed fallback"
  blanket built it as a vblank 50 Hz tune: the write SEQUENCE matches as a
  perfect prefix but under-runs ~20% = a guaranteed length partial (the
  Trap-C-looking flat pos-0 divergence is the CIA init-phase artifact —
  localize per-IRQ). Fix: when N rounds to <2, measure the exact
  entry-to-entry period (median of entry0 deltas; a 2-entry frame doubles
  one delta, the median discards it) and return $4025 iff it matches (±2).
  A 50 Hz-ish single-speed CIA rate is left 0 (a vblank build is
  equivalent). Regression-safe by construction: any member this changes was
  rate-wrong (never FULL). Also: call the writelog fallback for
  CANONICAL-play members (play == base+3), not only wrappers — the canon
  path never measured them.
- **Consumers:** DMC v4 `factory._cia_period_from_writelog` (commit 2114f21 —
  67 py65-unreadable cia_multispeed members → 56 build, +20 FULL; default
  latch $4025: Crazy_Mix/Love_Song/Magnum_Theme 2026-07-06).
- **5th occurrence — the LAYER the second constructor stops at (2026-07-22,
  Nice_Dream_2SID).** Round 81 cured the multi-SID sub-player constructor by
  making it call the canonical build (`_config_at_base` ->
  `_build_via_canon(base_override=)`), which fixed every TABLE/LAYOUT probe.
  But the C19 WEDGE probes (`_WEDGE_PROBES`) are applied by the *caller*,
  `dmc_v4_config` — one layer ABOVE `_build_via_canon` — so sub-players still
  came back with every wedge knob defaulted. **Lesson: "make the second path
  run the canonical build" is only a cure if you check WHICH LAYER the
  canonical build's parameters are actually attached at.** Grep for the probe
  table's call sites, not just for the constructor. Cure: factor the probe
  application into one `_apply_wedge_probes(path, cfg)` and call it from every
  constructor, including the bare fallback.
- **6th occurrence (2026-07-29, r130 — Big_GLORZ + Low_Frequency, +2 FULL, 0
  FULL-side carriers) — the init-probe SUCCEEDS with a plausible WRONG latch;
  CROSS-CHECK it against the measurement.** The py65 post-init $DC04/$DC05
  snapshot is only the latch the INIT RUN reached: KB's players program the hi
  byte at one site ($DC05=$26 → $2600) and the fine lo byte from a second site
  the sentinel'd init never executes — libsidplayfp's steady entry period was
  9828 = the canonical $2663. The old preference order ("init probe first,
  writelog only when init returns 0") structurally trusts the wrong layer.
  Cure: `_cia_period_crosschecked` — keep the init latch only when the
  measured median entry period agrees (±3 cyc); on a STABLE disagreement
  return `measured_period − 1`. The stability gate (≥80% of per-period
  estimates within ±3 of the median) keeps C18 phase-wrapper / mixed-rate
  members on their init value — the 4 unstable-measure members in the census
  were all FULLs whose init latch was truthful. Regression-safe by
  construction (a wrong steady rate accumulates a length tail, so no FULL can
  carry one); census: 502 CIA members, 2 carriers, both partial, both
  recovered. GENERAL RULE: a probe that CAN return a value is not thereby
  RIGHT — when ground-truth measurement is this cheap, cross-check instead of
  short-circuiting on the first non-zero layer. A defaulted
  knob is silently wrong music, but here a compensating mechanism hid it: the
  batch's write-stream RETRY rediscovered the parameter at verify time, so the
  VERDICT was right and the built `.sid` was right, while the stored `.usf`
  (written without the param) specified a different build. Symptom: a member
  reads FULL in the batch but a fresh build verifies partial. Diagnose by
  splitting the layers — verify the stored `.sid` (passes), diff the stored
  `.usf` against a fresh extract (identical), then rebuild FROM the stored
  `.usf` and compare bytes (differs). That last step is the one no routine gate
  performed; it is now a `dmc_mass_write --audit` invariant (see C20).
- **COROLLARY (the Principle §8, corpus-side):** any build input that a
  verify-time retry discovers MUST be written into the USF, not injected into
  the parsed object. A rebuild that needs information absent from the USF is
  the §8 failure whether the information comes from an engine library or from
  a batch jsonl. NB you cannot persist it by parse->write round-trip — the USF
  round-trip is not byte-stable (20/60 sampled files differ); push the value
  onto the CONFIG so the writer emits it natively, and refuse the member if it
  still does not reach the stored `.usf`.
