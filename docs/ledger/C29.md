### C29 — Track LOOP into an OUT-OF-IMAGE sector → engine sonifies live ZEROPAGE as notes

- **Problem shape:** a voice's track (orderlist) hits its `$FF` loop marker,
  and the loop-target position holds a garbage sector number PAST the
  sector-pointer table, so `secp_lo[n]|secp_hi[n]<<8` resolves to `$0000` (or
  another address below the load addr). The file image is all-zero there, so the
  naive sector decode is "note-0 forever"; the ORIGINAL, at runtime, reads live
  LOW RAM as note data — for the `$0000` case that is the 6510 I/O port
  (`$00=$2F` DDR / `$01=$37` port, the PSID environment defaults) then static
  zeropage, read via `LDA ($F8),y` with the sector pointer `$F8/$F9=$0000`. The
  write stream plays notes `$2F`(=47), `$37`(=55), then the static zp bytes as
  notes/prefixes — a real, reproducible outro, NOT a bug to clamp (strict
  write-stream policy). Presents as a deep first-divergence: a voice plays two
  "impossible" high notes then a held low note, where the rebuild plays note-0.
- **Canonical fix (extract-side; C26 shape but from LIBSIDPLAYFP not py65):**
  read what the engine reads. Gated on `_loops_offimage` (a `$FF` loop reaching
  a sector `< load`), capture the runtime low RAM
  (`_postinit_values(path, range(0x100))` — py65 CANNOT reproduce the
  emulator ENVIRONMENT's zeropage, ledger C9) and OVERLAY it onto the
  file-image `mem` before `_walk_track`, with two read-time corrections:
  (a) 6510 port offsets `$00/$01 = $2F/$37` (memwatch reads the RAM UNDER the
  port, not the port register — hardcoded PSID reset value, pc-trace-confirmed
  `[0000]{2f}`/`[0001]{37}`); (b) sector pointer `$F8/$F9 = $00` (during the
  read they hold the `$0000` base). `_simulate_sector` then decodes the true
  endless outro; the off-table reach model picks up the new notes/instruments
  automatically (Killer_Beat's `$FF00` region = instr-7 note-28 off-table freq).
- **Regression-safe BY CONSTRUCTION:** the overlay only changes the DECODE of
  out-of-image sectors, and a sector's decode only affects the write-log if it
  is PLAYED. A played out-of-image sector was always mis-decoded (image zeros ≠
  runtime), so any member the change touches was already non-FULL; an unplayed
  sector's decode change is byte-identical. The overlay writes only `$00-$FF`,
  which nothing else in the extract reads → no FULL can regress (proven: full
  `tools/regression.py` green 0-regr all 7 families; a no-OOB FULL builds
  byte-identical MD5 old-vs-new).
- **Combines** C26 (out-of-image data → read runtime RAM) + C9 (py65 can't
  reproduce the environment → measure from libsidplayfp). Distinct from C26's
  init-UNPACKER (there the member's OWN init generates the tables and py65 runs
  it); here the sonified bytes are the EMULATOR ENVIRONMENT's zeropage + the
  6510 port, which only libsidplayfp holds.
- **Boundary / residue:** works when the sonified low RAM is STATIC during play
  (taint-confirm `$0000-$00FF`: for the DMC player only `$F8/$F9` are written,
  and those read `$00` from the voice's own `$0000` sector pointer). A member
  whose sonified zp region has a byte WRITTEN during play (dynamic) keeps that
  byte wrong (defaulted 0) = honest residue; the first divergence still moves
  deeper (Lens 3 win). Off-table dynamic residue + the 2SID multi-subtune
  limit (unrelated) account for the 29 members that stayed partial.
- **GENERALIZED (2026-07-23, Super_Seven 2/2 — the truncated-copy class):**
  the gate is now ANY PLAYED sector whose 256-byte window leaves defined RAM
  (below load / overlapping banked-in ROM / wrapping past $FFFF) — not just
  a `$FF`-loop target (`_offimage_sectors`, replacing `_loops_offimage`);
  the window bytes come from `siddump --peek-post-init` (`_cpu_peek`), a
  CPU-EYE read through the MMU that returns banked ROM **including
  psiddrv's patched KERNAL vectors** ($FFFC/$FFFD → the relocated driver
  entry — invisible to a RAM-only memwatch AND absent from ROM files), the
  6510 port, and libsidplayfp's power-on RAM pattern in one mechanism; and
  `_postinit_window` seeds py65 RAM with that pattern (`_poweron_fill` +
  the psiddrv `$0-$3FF` zero) so unwritten bytes read as the engine reads
  them (Super_Seven: the wrapper's copy truncates at $46FF → secp_hi[9]
  reads pattern $FF → sector 9 at $FFEF = KERNAL tail; the $4C JMP opcodes
  ARE the audible "note 76"). ⚠ OVERLAY ONLY UNDEFINED BYTES (≠ image,
  ≠ init-written, tested vs a reference seed): the pre-scan also walks
  GARBAGE tune records, and a spurious window overlapping real player data
  let the full-init peek snapshot clobber the landing view — regressing
  Pour_le_merite sub 0 + Abyssal_Karma subs 1-4 (priming read from smashed
  state) until the defined-set guard landed.
- **3rd OCCURRENCE (2026-07-23, Trailways_A FULL — the POINTER-BYTE class):**
  the byte that leaves defined RAM can be the SECTOR-POINTER FETCH itself,
  not the sector window: a track byte selects a sector # past the pointer
  tables (Trailways_A: $11 into 10-entry tables), pushing `secp_hi[n]` past
  the image end. The engine reads power-on $FF there → the sector is at
  $FFCA (KERNAL tail: the CHKOUT `JMP ($0320)` operand $20 IS the audible
  note 32); the zero-filled image view mislocated it at $00CA (live-zp
  class) — so the WINDOW machinery peeked the wrong address and decoded
  note-0 rows. TELL: the first divergence is a NOTE-VALUE shift (orig =
  ours + K) on every voice with transp/otrk/sectpos identical — the walk is
  in lockstep, the CONTENT differs. FIX: `_undefined_secp_reads` pre-pass
  (mirrors the `_offimage_sectors` walk, collects pointer-fetch addresses
  outside the image) served by `_cpu_peek` BEFORE sector resolution;
  post-init memory is exempt (`_postinit_window` already seeds
  `_poweron_fill`). Same regression-safety argument: only mislocated (=
  already-wrong) sector decodes change.
- **5th OCCURRENCE (2026-07-27, Harti/Memomania sub 3 — the ORDERLIST-POINTER
  class + a scan/walk consistency fix):** the out-of-image read can be the
  TRACK (orderlist) POINTER ITSELF, not a sector. A tune-table track pointer
  lands in banked ROM (Memomania V1 ptr = `$F256` = KERNAL, all other pointers
  `$C2xx`), so the ENGINE reads the WHOLE orderlist from ROM and plays it
  (sector 1 melody + a transpose walk); the file-image zero-fill decoded sector
  0 forever. FIX (extract-side): `_offimage_track_ptrs` pre-pass overlays the
  CPU-eye window at any track pointer whose 256-byte window overlaps banked ROM
  (`$A000-$BFFF` / `$E000-$FFFF`), BEFORE the secp-read + sector walks (both
  read `mem[tp+pos]`); it shares the refactored `_overlay_offimage_windows`
  helper with the sector overlay. ⚠ STATIC ROM ONLY, deliberately: a
  below-load / zeropage track pointer reads DYNAMIC RAM the stability filter
  can only serve as 0 (= the old zero-fill), so overlaying it merely MOVES a
  divergence (it slightly worsened Flash/Kan-Kan 2→0 when the gate included
  `< load`) — the same static-vs-dynamic boundary as the $0000 class. ⚠ AND
  GATED TO NON-POST-INIT MEMBERS (same `if not (data_post_init or post_sub)`
  guard as `_undefined_secp_reads`): for a `data_post_init` / compilation
  member `mem` is the RUNTIME RAM, and a `$A000-$BFFF`/`$E000+` orderlist
  address there is GENERATED RAM, not banked ROM — peeking the CPU-eye would
  clobber the init-generated orderlist with ROM bytes (Kan-Kan: init-unpacked
  orderlist at `$A3A1` is RAM; the raw-image scan sees `$0000` there but the
  post-init `mem` sees `$A3A1`, so classify the OVERLAY gate on the SAME `mem`
  the walk uses, and skip it where the mem is already runtime-correct).
- **SCAN↔WALK CONSISTENCY (general correctness, same commit):**
  `_offimage_sectors` and `_undefined_secp_reads` MUST mirror `_walk_track`'s
  transpose handling — the byte AFTER a transpose command is a sector number
  UNCONDITIONALLY (orig `$10FE-$1101`: `INY / LDA($f8),y / TAY`, no
  re-dispatch), EVEN when that byte is itself `>= $80` (Memomania `$F3 $A5`
  plays sector `$A5`, not transpose `$A5`). The old scans only special-cased a
  post-transpose `$FE/$FF` (C34) and re-dispatched otherwise, so they MISSED a
  post-transpose off-image sector's secp/data reads and never overlaid them —
  leaving `_walk_track` (which decodes it correctly) to read image zeros and
  spuriously self-loop. Equivalent for `nb < $80` (common) and `nb >= $FE`
  (C34); byte-identical over 227 members (golden diff). LESSON: the two
  off-image SCANS are meant to be exact mirrors of `_walk_track`; when one
  gains a dispatch subtlety (C34, this) the others must too, or an off-image
  read is silently un-overlaid.
- **RESIDUE (Memomania does NOT reach FULL — a clean C29 dynamic wall):** its

  `$A5` is past the sector-pointer table so `secp[$A5]` = off-image
  `$C982/$C9A4` = `$00` → sector `$A5` = address `$0000` = LIVE ZERO PAGE. The
  orig sonifies dynamic engine state there (the port bytes `$00/$01` still
  match — first divergence lands exactly at the port→dynamic-zp transition,

  (6 f1 partials with out-of-image track pointers; only the ROM ones are
  helped, the `$0000`/zp ones stay dynamic residue) + counts: [[project_dmc]].
