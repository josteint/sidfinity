### C5 — Detection ≠ FULL
- **Canonical:** accepting a member past the factory's detection gate just moves
  it to its NEXT failure mode (cia / partial / error) — it is NOT a FULL. The
  verify PARTIALS, not the detect-rejects, are the FULL bottleneck.
- **Status:** 📋 methodology — see [[reference_divergence_census]],
  `tools/divergence_census.py`.
- **Boundary:** any wide-family residue triage.
- **Consumers:** DMC v5 reloc@$10E5 (2026-06-18: cleared the reloc gate → 32
  surfaced as cia_multispeed, only 5 reached FULL).
- **REFINEMENT (2026-08-22) — SCORE AN UNBLOCKING LEVER BY DEPTH, NOT BY FULL.**
  The same trap one step later: a fix that unblocks a residue CLASS usually
  does not take members to FULL, it moves each member's first divergence to
  the NEXT bug. Counting full/partial then reports the whole round as "0
  gained" and hides the entire effect. Score it with the FIRST-DIVERGENCE
  DEPTH HISTOGRAM over a stratified subset (`tmp/v5_depth_measure.py`), and
  report `deeper / shallower / unchanged` — shallower is the regression
  signal, and it stays visible even when nothing reaches FULL. Worked example:
  the DMC v5 family-4 startup lever moved the 1-63 bucket 58 -> 13 with
  deeper 49 / shallower 0 / regressed 0 and ZERO members reaching FULL; on a
  full/partial score it would have read as a no-op and been reverted.
