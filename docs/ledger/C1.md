### C1 — A control value swept over time (pulse-width, filter cutoff, any contour)
- **Canonical:** `SweepEnvelope(start, phases=[(rate, frames)], loop)`. Capture
  with `pipelines/dmc/v5/extract/to_usf.py:_capture_env`; rebuild with
  `from_usf.py:add_env`.
- **Status:** ✅ SHARED (USF schema + `_capture_env` + `add_env`).
- **Boundary:** piecewise-constant-rate contours. A bounded bidirectional
  oscillator is the special case `start + [(+s,n),(−s,n)], loop=0` — verified
  losslessly expressible (decision-1 gate, 2026-06-18).
- **Consumers (canonical):** DMC `pulse_env`, `filter_env`, `default_pulse`,
  `default_filter`. **basic_program per-frame PWM — ✅ LANDED (commit f2eaabf,
  Cascading FULL)** — a free-running per-voice pulse-width sweep PROGRAM: each
  voice runs an independent automation orderlist (a value-table of distinct
  period bytes + RLE sections `(offset, period_len, repeats)`; dedup reuses
  identical period runs). The single-`SweepEnvelope` form was insufficient — the
  real signal is a multi-section program (~40 sections/voice), so it generalizes
  the contour into a sectioned orderlist (still parametric/musical, NOT a raw
  period table — the table holds only distinct periods, sections index them).
  This is the `default_pulse` continuous analog, not per-instrument. Player =
  a 6502 sweep walker advancing at a FRACTIONAL rate (mod_inc/256 ticks per
  play() = the BASIC-loop rate, not 50Hz); notes re-timed onto the sweep-tick
  clock; PW emitted before the note check ([PW][note] within a tick). Confirms
  C1 generalizes to a 5th family. Remaining basic_program modulation tunes need
  per-voice gating + arp (Pong/Doom_Comer) or filter-`$D416` modulation
  (Sullen/Pepper/Brickout, not yet handled).
- **DIVERGENT forms of the same DOF across families** (Move-1 decisions D1/D2,
  see [the_move-1_plan.md](../the_move-1_plan.md) all-families review
  2026-06-18 — unify onto `SweepEnvelope`; a CANDIDATE UNIFIED FORM — the

- **DMC one-shot filter contour (2026-08-12/13) — the C1 form absorbed a
  driver deconstruction and the typed home GENERALIZED:** the SilverFox
  4k_Byter appended sequencer (staircase + ramps on one filter def's INIT
  CUTOFF, then terminal hold) was simulated in the factory probe and
  emitted as `filter_mod` — whose schema grew along the musical axis:
  `stop_phase` now OPTIONAL (single tap) and a `once` marker (one-shot,
  terminal hold) beside the FC/Ed looped two-tap LFOs. ONE composer
  interpreter (`playfmod`, generalized: 1-2 taps, loop/hold) serves all
  carriers — the cross-engine-reuse test (§9.4) passing literally. Measured
  boundary: def clone-and-remap could NOT encode it (25 distinct sampled
  claim values vs 16 def slots) — when a contour's sample count exceeds the
  format's slot budget, the parametric contour is not just prettier, it is
  the only faithful representation.

- **The two remaining Ed filter-def DRIVERS deconstructed (2026-08-16) —
  `filter_mod` grew `res` / `period` / `loop_to` (owner-approved):** the
  last two mechanism params (`filterdef_anim` Cliche_Beat, `filterdef_anim3`
  Only_Ones — multi-phase SMC drivers ramping def RESONANCE cells then
  walking triangle LFOs into cutoff cells) are now simulated play-by-play
  in the extract (`pipelines/dmc/v4/extract/filterdef_anim_lift.py`) and
  emitted as contour entries; the composer's transcribed driver emitters
  (playfda/playooa, ~150 lines) are DELETED. Three musical-axis growths:
  `res` — the tap feeds the prog's resonance cell (the principle's own
  vibrato example already had depth-family params; resonance is cutoff's
  sibling knob); `period=N` — the contour clock (plays per step;
  `init_phase` generalizes to "plays into the contour", solving tick-grid
  alignment with no extra field — Cliche's 509-run cycle collapses to 6
  readable runs); `loop_to=K` — loop re-entry run (one-time lead-in +
  cycle; generalizes `once`/loop). A prog may now carry SEVERAL entries
  (res sweep + cutoff LFO) — the container became a LIST. The composer
  grew ONE new-form walker (stream-of-pairs, 16-bit SMC pointer, so >255
  runs work — Only_Ones' floor-jitter lists are irreducibly ~400 runs,
  the No_End "authored curve" precedent). METHOD: every emitted entry is
  REPLAY-VERIFIED against the simulation by a Python mirror of the walker
  (one spec, two implementations — the C32 observe-don't-fit assert).
  ⚠ TRAP RECORDED: the driver runs BEFORE the play body, so its counters
  already decrement AT play 0 — a sim indexing ticks one play late stays
  invisible on note-init-sampled cells (Cliche verified FULL!) and only
  surfaced on Only_Ones' continuously-clamped sweep. Sim semantics =
  "state visible to play p's body". Both carriers FULL at full
  songlength; corpus synced.
- **DMC DIRECT cutoff LFO (2026-08-13) — `filter_mod` grew a modulation
  ROUTING marker:** SilverFox/No_End's appended play-vector cycler walks a
  256-entry authored cutoff table at 1 entry/play and writes `$D416`
  ITSELF (the canon cutoff store is NOPed — C19 48th occ), bypassing the
  def cells entirely. Typed as a `filter_mod` entry with `target: cutoff`
  (`direct` in the USF text): same delta-run steps + walker, the single
  tap stores to the register instead of `fdinit+slot`. The table is NOT an
  exact sine (88/256 best-fit errors) — an authored curve, so the exact
  delta-run encoding IS the faithful musical form (a fitted sine would be
  the C32 "observe, don't fit" violation). Routing (sampled-at-note-init
  vs free-running-to-register) is a small musically meaningful enum, not
  an engine kind.
